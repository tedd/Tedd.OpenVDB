# Tedd.OpenVDB (.NET 11)

Managed C# OpenVDB storage and volume algorithms for **.NET 11 Preview 7**. The former C++/CLI wrappers have been replaced. The library has no native runtime dependency.

**The port is incomplete.** The standard `Tree4<T,5,4,3>` hierarchy, substantial tree/math/volume APIs, and interoperable format-225 archives are implemented. Configurable tree families, point grids, meshing, many level-set and simulation tools, legacy/delayed I/O, NanoVDB and AX remain. See [coverage and limitations](docs/PORT_STATUS.md) and the [upstream inventory](docs/UPSTREAM_INVENTORY.md).

Reference: [OpenVDB 13.0.1](https://github.com/AcademySoftwareFoundation/openvdb/tree/f42248c35a9f7bb30641a8a74d9075ce7d1ddcaf), commit `f42248c35a9f7bb30641a8a74d9075ce7d1ddcaf`. Work is on `main`; the wrapper replacement was committed as `5eb1137`.

## Build and test

Install the SDK pinned in `global.json`:

```powershell
dotnet build Tedd.OpenVDB.slnx -c Release
dotnet test Tedd.OpenVDB.slnx -c Release
dotnet run --project samples/VoxelBlocks -c Release
dotnet run --project benchmarks/Tedd.OpenVDB.Benchmarks -c Release
dotnet pack src/Tedd.OpenVDB -c Release -o artifacts/packages
```

The managed tests use committed fixtures generated by native OpenVDB. They require no native installation or network after NuGet restore. [Reference scripts](reference/README.md) reproduce the independent comparisons. CI is configured for Windows/Linux and hardware intrinsics on/off; local validation results are recorded separately in [VALIDATION.md](docs/VALIDATION.md).

## NuGet publishing

Release builds produce `Tedd.OpenVDB.<version>.nupkg` and `.snupkg` in `src/Tedd.OpenVDB/bin/Release`, including XML API documentation, Source Link metadata, the README, license and third-party notices. To collect the packages in one directory after building:

```powershell
dotnet pack src/Tedd.OpenVDB/Tedd.OpenVDB.csproj -c Release --no-build -o artifacts/packages
```

Configure a GitHub Actions repository secret named `NUGET_API_KEY` with permission to publish `Tedd.OpenVDB` on NuGet.org. Set `<Version>` in `src/Tedd.OpenVDB/Tedd.OpenVDB.csproj` to a new package version, retaining a prerelease suffix while the port is incomplete. After a push to `main` passes every Windows/Linux and intrinsics test job, CI publishes the package and symbols and creates a `v<version>` tag. An existing version or tag is skipped. Pull requests and other branches only run validation.

Publishing uses [tedd/publish-nuget-neo](https://github.com/tedd/publish-nuget-neo), matching the Tedd.BitUtils release workflow. The publish job has `contents: write` permission for version tags; test jobs have read-only access.

## Voxel storage

```csharp
using Tedd.OpenVDB.Math;
using Tedd.OpenVDB.Tree;

var blocks = new VdbTree<ushort>(background: 0);
var chunk = new CoordBBox(new(-32, -32, -32), new(-1, -1, -1));
blocks.Fill(chunk, 1); // 32,768 blocks represented by uniform tiles
var edit = blocks.GetAccessor();
edit.SetValueOff(new(-16, -16, -16), 0);
edit.SetValueOn(new(-15, -16, -16), 2);

ushort[] renderBuffer = new ushort[(int)chunk.Volume];
blocks.CopyToDense(chunk, renderBuffer); // Z contiguous, then Y, then X
blocks.Prune();
```

Activity and value are independent. `SetValueOff(c)` retains the value; `SetValueOff(c, 0)` also writes air. `IsEmpty` follows native structural emptiness; use `HasActiveVoxels` to ask whether anything is active. Signed coordinates and inclusive boxes support the full Int32 domain.

Tree APIs include sparse/dense fill, clipping, topology operations, merge policies, node transfer, background replacement, mutable value traversal with depth limits, `LeafManager<T>` auxiliary buffers, allocated-node traversal, cached `NodeManager<T>` reductions and filtered `DynamicNodeManager<T>` traversal. Keep one accessor per worker and synchronize writes externally. Structural changes invalidate accessor caches, static managers and tree-wide mutable value handles. Node-local handles track their direct table and remain valid across sibling edits; dynamic parallel callbacks must stay within their own subtree. Direct leaf references remain managed objects but may be detached by structural edits.

`EnumerateValues` visits a tile once. `EnumerateActiveVoxels` expands tiles. `VoxelizeActiveTiles(maximumNewLeaves)` supports an explicit preflight allocation limit. Dense grids support both XYZ and ZYX layouts.

## Standard .vdb archives

Format 225 supports Int32, Int64, Float, Double, Bool, Vec3i, Vec3s/Vec3f, Vec3d and restricted topology-mask grids. Archives support heterogeneous grids, shared-tree instances, file/grid metadata, opaque metadata, affine and nonlinear frustum maps, active-mask/zlib/Blosc-LZ4 compression, and real-valued half encoding.

```csharp
using Tedd.OpenVDB;
using Tedd.OpenVDB.IO;

var materials = new Grid<int> { Name = "materials" };
materials.Tree.SetValueOn(new(1, 2, 3), 7);
var occupied = new MaskGrid { Name = "occupied" };
occupied.SetValueOn(new(1, 2, 3));

using var stream = new MemoryStream();
VdbFile.WriteArchive(stream, new VdbArchive([materials, occupied]),
    options: new() { Compression = VdbCompression.Zlib | VdbCompression.ActiveMask });
stream.Position = 0;
VdbArchive copy = VdbFile.ReadArchive(stream);
```

`Read<T>` and `Write<T>` remain single-grid conveniences. `ushort` supports in-memory material storage; standard registered archive types do not include a UInt16 grid. Compressed BloscLZ/Snappy/Zstd frames, bitshuffle, forward instance references, legacy versions, point/custom layouts and delayed loading remain unsupported. Native default Blosc LZ4 with byte shuffle and Blosc zlib reads are implemented. [Native I/O provenance](reference/IO_VERIFICATION.md) links the verified formats and profiles.

Read options limit bytes, estimated allocation, grids, nodes and metadata. Streams remain open unless `leaveOpen: false`. Use a temporary output file before replacing a saved archive: a stream failure can leave partial output.

## Algorithms and numerical types

Implemented tools include exact/tolerance/inactive pruning, signed flood fill, 6/18/26-neighbor morphology with tile policies, level-set spheres, CSG, scalar/vector compositing, mean/Gaussian/median/offset filters with transformed masks, dense conversion, level-set interior/fog conversion and segmentation, surface measurements, level-set normalization/tracking/resize and filters, grid differential operators, and weighted statistics/histograms. Point/box/quadratic sampling supports scalar and vector fields, staggered Vec3 fields, world coordinates and dual-grid transforms. Math includes vectors, matrices, quaternions, frustum/camera maps, ray/DDA operations, finite differences, WENO/Godunov kernels and gradient/curvature/WENO stencils.

Some native behaviors differ from their comments. In particular, CSG may leave unused nodes in its second input; CSG copy with unequal backgrounds depends on native thread partitioning. Managed copy matches serial native execution. The [CSG record](reference/CSG-CONFORMANCE.md) and [math record](reference/MATH_VERIFICATION.md) describe these boundaries.

## Memory and performance

The hierarchy uses 8³ leaves, 16³ lower tables and 32³ upper tables. Contiguous unmanaged value arrays and sparse child-reference tables reduce GC reference scanning. Mask operations use SIMD with scalar fallback, popcount and trailing-zero enumeration. Span transfers, local array references and completely initialized `GC.AllocateUninitializedArray` buffers support JIT optimization. Leaf-buffer swaps reuse arrays and retain managed references safely across compacting collections.

No speedup over .NET 10 or native OpenVDB is asserted without controlled measurement. The included benchmark is a throughput/allocation smoke test; see [performance notes](docs/PERFORMANCE.md).
