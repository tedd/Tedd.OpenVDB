# Tedd.OpenVDB

Tedd.OpenVDB is an independent, managed C# port of core [OpenVDB](https://www.openvdb.org/) storage, archive, math, and volume-processing facilities for .NET 11. It targets sparse voxel-world and volumetric-data workloads without requiring a native runtime.

> [!WARNING]
> This is a preview port, not a complete 1:1 replacement for upstream OpenVDB. Its supported surface and compatibility limits are documented in [Port status](docs/PORT_STATUS.md).

## Capabilities

- Sparse Tree4 voxel storage with tiles, accessors, topology operations, dense transfers, pruning, traversal, and node managers.
- Managed OpenVDB format-225 archives for the supported grid, metadata, transform, compression, and instance families.
- SIMD-aware masks, span-based transfers, pooled codec workspaces, and NativeAOT-compatible storage paths.
- Volume topology, level-set, sampling, filtering, resampling, numerical, mesh-conversion, and CPU preview-rendering tools within the documented scope.
- Point attributes, point-index grids, particle atlases, paged point streams, and in-memory PointDataGrid composition.
- Native differential fixtures and managed unit coverage; no native OpenVDB installation is needed to build or test the library.

## Requirements

- The .NET SDK pinned by [global.json](global.json).
- An x64 development environment is recommended for the SIMD and NativeAOT validation paths.

## Build and test

~~~powershell
dotnet build Tedd.OpenVDB.slnx -c Release
dotnet test Tedd.OpenVDB.slnx -c Release
dotnet run --project samples/VoxelBlocks -c Release
dotnet run --project benchmarks/Tedd.OpenVDB.Benchmarks -c Release
dotnet pack src/Tedd.OpenVDB/Tedd.OpenVDB.csproj -c Release -o artifacts/packages
~~~

The committed test fixtures were generated by native OpenVDB, but the managed build, tests, samples, and package do not require a native OpenVDB runtime. Fixture generators and reproduction instructions are in [reference](reference/README.md).

## Quick start: sparse blocks

~~~csharp
using Tedd.OpenVDB.Math;
using Tedd.OpenVDB.Tree;

var blocks = new VdbTree<ushort>(background: 0);
var chunk = new CoordBBox(new(-32, -32, -32), new(-1, -1, -1));

// Represent a 32 x 32 x 32 region as a uniform active tile.
blocks.Fill(chunk, 1);

var accessor = blocks.GetAccessor();
accessor.SetValueOff(new(-16, -16, -16), 0);
accessor.SetValueOn(new(-15, -16, -16), 2);

ushort[] dense = new ushort[(int)chunk.Volume];
blocks.CopyToDense(chunk, dense);
blocks.Prune();
~~~

Activity and value are separate concepts. `SetValueOff(coordinate)` preserves the stored value, whereas `SetValueOff(coordinate, 0)` also writes the background value. `IsEmpty` describes structural emptiness; use `HasActiveVoxels` for activity.

## Archive interoperability

The implemented archive reader and writer target OpenVDB format 225. The current supported set includes scalar, Boolean, Vec3, and restricted-mask grids; heterogeneous archives; grid instances; supported metadata and transforms; active masks; zlib; and the c-blosc codec families. Unsupported formats, types, and delayed-loading behavior are enumerated in [Port status](docs/PORT_STATUS.md).

Treat an archive round trip as an explicit compatibility boundary: validate files against the documented supported types and versions before adopting the library for a production pipeline.

## Validation

The 0.1.0-preview.7 checkpoint passed 20,990 tests in Release, Debug, and scalar-intrinsics-disabled configurations. The NativeAOT voxel sample published and executed on Windows x64, and the native fixture manifest verified 417 files totaling 195,864,993 bytes. These are correctness gates, not performance claims. See [Validation](docs/VALIDATION.md) for commands, timings, fixture provenance, and scope.
